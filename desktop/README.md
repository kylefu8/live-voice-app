# Live Voice Windows

**简体中文** | [English](README.en.md)

面向 **GPT-Live-1 实时语音模型**的 Windows 客户端。当前修订为 **0.2.0-2**。[统一下载](../docs/DOWNLOADS.md) · [首次使用](../docs/GETTING_STARTED.md) · [界面截图](../docs/SCREENSHOTS.md)

当前正式项目版本为 **0.2.0**，见 [发布说明](../docs/releases/windows-0.2.0.md)。应用内版本与程序文件版本一致。

Windows 与 Android 的核心功能保持同一范围：自然语音对话、语音与后端独立设置和连接测试、风格与模型参数、深浅色/系统主题、中英文、本机文字历史。聊天、提问和口语练习都从同一个对话入口开始。历史记录支持改名、删除和由已配置后端生成标题。Windows 的“设置 → 连接管理 → 生成配置二维码”从已保存的连接生成加密二维码，口令至少 4 个字符。

两端分别直连模型服务，各自保留历史。电脑不充当手机对话中转，也不提供账号、云同步或跨设备续聊。手机端可在“设置 → 连接管理 → 扫码导入连接”导入生成的二维码。

## 运行

“设置 → 关于”显示 Windows 客户端版本、作者及 GitHub 仓库地址。版本来自 package.json，与打包版本同步；仓库地址可选中复制。

0.1.10-2：会话进行中禁用音色、输入输出设备、两类连接编辑和测试，结束后恢复。连接中/结束中暂停参数保存。语气、语调、节奏仍是模型偏好，收到服务确认不等于听感已验证。

0.1.10-1：设置分为对话设置、连接管理、音频设备、外观与语言、关于；手机联动位于连接管理内。会话中可直接打开对话设置，保存后应用语气、语调、节奏、指令与时长。时长从最初连接时刻计算；小于已用时长时不立即结束通话，而是提示换更长时长。音色、音频设备与连接变更仍在下一次会话生效。后端参数保存后用于下一次请求，正在处理的请求保留原快照。风格更新等待对应服务确认，未确认时如实提示；确认代表指令已接收，效果需从后续回复观察。

0.1.10：新安装或缺失字段时，后端默认最大输出 32768、联网搜索开启；已有手动保存的参数保持不变。Windows 当前仍保存文字历史，录音开关由已支持双方录音的 Android/iOS 客户端提供。

构建产物位于项目 `../releases/windows/`，打开对应版本目录中的 `Live Voice-win32-x64/Live Voice.exe`。必须保留同目录的运行文件，不能只移动 exe。程序已包含 Electron，不需要另装 Node 或启动 PC 网页。

当前提供未签名的 x64 便携发布包，尚无商店安装和自动更新。系统如给出安装/安全提示，应由设备使用者判断，不自动绕过防护。

首次使用：进入“设置 → 连接管理”，分别输入语音和可选后端的 endpoint、模型/部署名、鉴权方式与 API key，保存后可测试。回“对话”直接开始；需要练口语时，在对话中自然说明即可。麦克风只在点击开始后请求。需在 Windows 隐私设置允许桌面应用使用麦克风。

0.1.1 起，Azure OpenAI 资源根地址（`https://<resource>.openai.azure.com`）在测试与实际请求时自动补为 `/openai/v1`；官方 OpenAI 根地址补为 `/v1`。已填写完整 API 路径的地址保持不变，自定义网关不猜测前缀。旧版本请在 Azure 地址后手动加 `/openai/v1`。

语音测试仅建立并关闭短会话，不验证实际音频；后端测试发送一次最小 Responses 请求，不验证搜索。测试和实际聊天都可能产生服务用量。

0.1.3 起，会话页分别显示语音连接与后端状态，包括“后端处理中”、等待时间、已返回和失败。等待时间是本机请求耗时，不代表模型内部推理进度。后端 Token 预算包含推理及最终回答；若服务明确报告 `max_output_tokens` 耗尽，页面会给出针对性提示，不自动提高预算或重试。

0.1.4 根据委托与转写的会话时间戳处理连续语句，避免迟到的同句转写直接取消后端。当前用 1.5 秒转写间隔及稳定等待作为应用侧启发式规则，并非服务提供的完整话轮边界；可能增加少量响应等待。已发出的只读后端请求如需补充同句输入，最多替换一次；真正的新语音取消旧结果，服务错误不自动重试。真实麦克风上的停顿、打断和回声仍需单独验收。

0.1.5 统一结束请求的确认与超时流程，最长等待 15 秒，重复关闭窗口不会提前中断确认。后端不再固定只取最近 80 段，而是发送当前保留的最多 500 段；发送内容上限 256 KiB UTF-8 JSON，超限优先保留开头用户信息、相邻回答及最新问题，裁剪较旧的中间内容。这仍是应用容量限制，不等于模型完整上下文窗口，也不提供跨会话记忆。设置页中英文均说明该限制。

0.1.6 增加官方 sideband 关闭确认备用路径：正常关闭 8 秒未收到确认，或数据通道已经不可用时，由主进程连接同一服务的现有会话并发送一次结束请求。密钥保持在主进程，只收到 `session.closed` 才标记已确认；总等待仍为 15 秒，失败后如实显示未确认并释放本地资源。没有新增中转服务器或自动重连会话。

0.1.7 移除独立的“通用模式 / 练口语模式”选择，桌面端只保留一个自然对话入口；通用对话仍可按用户要求练习口语、解释表达或切换话题。旧设置中的 `practice` 会在读取时迁移为 `general`，旧历史记录保留并与新记录一起查看，不再按模式筛选或显示模式标签。

0.1.8 增加本机历史管理。记录没有标题时显示“对话 · 日期”；保存后若后端已启用并配置，会异步用一段不超过 6000 字符的文字摘录生成标题，失败时保留日期标题，不阻塞结束会话或关闭应用。历史详情支持应用内改名和删除确认，自动标题结果不会覆盖手动改名或恢复已删除记录。

## 音频设备

在“设置 → 音频设备”选择麦克风输入和扬声器/耳机输出，再点击“保存音频设备”。默认跟随 Windows 系统设备，明确选择的设备不可用时会提示重新选择，不静默切到其他设备。选择从下一次对话生效；设备 ID 只保存在本机，不进入配置二维码。

- “刷新设备 / 授权麦克风”重新获取设备列表；需要时短暂取得麦克风权限以显示设备名称，随后释放。
- “测试麦克风”只显示实时音量，不监听回放、不保存、不上传，15 秒后自动停止，也可手动停止。
- “播放测试提示音”在所选输出设备播放短而轻柔的双音提示；请自行确认是否能从该设备听到。它不调用模型。
- 离开音频设置、开始对话或退出会停止设备测试。对话过程中禁用设备测试，避免重复占用麦克风。

## 保存与导出

- 配置与历史放在当前用户 `%APPDATA%/LiveVoiceDesktop`，独立于 Android、PC 网页和其他项目。
- 完整连接（包括 key）由 Electron `safeStorage` 使用 Windows 系统加密保护；不可用时拒绝保存，绝不退回明文。
- 主进程负责凭据、模型请求和加密导出。界面仅收到 key 遮罩；新 key 为密码输入，不提供显示与复制。
- 主题与语言立即保存；模型参数在各自明确点击保存后生效。新会话使用已保存参数快照；通话中保存语音与后端参数会按上述规则更新当前会话。音色需要新会话。
- 历史仅保存本机文字，最多 50 条、总计 1MB，有单条长度限制；标题最多 60 个 Unicode 字符。保存标题会向已配置后端发送简短摘录并产生少量用量，不保存录音、不从历史自动恢复上下文。
- “手机联动”选择已保存的语音/后端连接，输入并确认导入口令，再生成、保存 QR PNG。只导出连接，不导出历史或模型偏好；二维码不含口令。
- 离开手机联动页面会清除导出口令和当前二维码。下载的二维码需自行保管；换口令不撤销旧码，撤销访问需在服务商处更换 key。

## 开发

本机使用项目内 Node 24.21.0、Electron 44.4.3、esbuild 0.28.2、@electron/packager 20.3.0。

```powershell
# 在 desktop/ 运行，使用 Node 24
npm ci
npm test
.\build.ps1
npm start
.\build.ps1 -Package
```

Windows 包装脚本使用 `../work/toolchain/electron-44.4.3/electron-v44.4.3-win32-x64.zip` 官方归档，构建前已对照 Electron npm 包内的 checksums.json 核对 SHA-256。每次产物使用新目录，不覆盖旧发行包。

- `main.mjs` / `preload.cjs`：Electron 沙箱、固定 IPC 白名单、音频权限与退出。
- `store.mjs` / `services.mjs`：原子保存、历史改名/删除与后台标题、加密凭据、连接测试、会话快照、后端与二维码导出。
- `renderer/`：桌面界面与浏览器 WebRTC 控制器。
- `scripts/build.mjs`：打包引用的 PC 加密/测试模块和原生纯协议模块，不复制其他项目私有配置。
- `CONTRACT.md`：模块接口；协议来源见 `../design/native-protocol.md` 与 `../design/config-qr-v1.md`。

验证范围和实际完成结果见 [VERIFICATION.md](VERIFICATION.md)。

搜索来源默认折叠为带数量的一行入口，展开后在限高列表内独立滚动，不随来源数量增长占满字幕区。新会话或新一批搜索结果到达时恢复折叠；查看当前来源时的普通字幕更新不改变展开状态。

# UI v2 规格说明

设置部分已被用户后续确认的 [settings-v3.md](settings-v3.md) 更新：加入双语、独立手动连接配置、密钥遮罩和说话风格，取消固定对话语言。以下保留 v2 的设计依据。

后续变更：Android 0.3.0 已按用户确认加入底部导航、固定会话操作区及双方自动录音。录音范围以 [native/README.md](../native/README.md) 和 [ADR 0002](../docs/adr/0002-android-local-recordings.md) 为准；下文关于录音“尚未确认”的描述仅保留为历史设计背景。

这是[手机语音 App 规划](../README.md)的第二版静态 UI 规格，补充深色模式、历史会话查看和模型参数配置。它用于指导概念稿与后续可点击原型，不代表 App 已实现，也不替代 Android 真机语音链路验证。

## 范围和已确认边界

- 首页仍然以“选择模式 → 开始对话”为主路径，通用模式和口语练习模式共享自然交流与随时打断的通话页。
- 首版支持深色模式，并建议提供“跟随系统 / 浅色 / 深色”三种主题选项。
- 首版可以查看历史会话；列表按日期、模式区分，详情只读，不自动恢复上下文。
- 首版提供 GPT-Live-1 实时语音模型和可选后端模型的参数配置入口。
- 手机直连已导入的模型服务。二维码导入或更新连接凭据属于连接配置流程，与模型参数页分开。
- 本规格不确认录音保存、云同步、跨设备历史、账号体系、长期上下文恢复或历史导出。

## 导航结构

```text
首页
├─ 模式选择：通用 / 练口语
├─ 开始对话
├─ 历史会话
└─ 设置
   ├─ 模型参数
   │  ├─ GPT-Live-1 实时语音
   │  └─ 可选后端模型
   ├─ 连接配置
   │  └─ 扫码导入 / 更新
   └─ 外观
      └─ 跟随系统 / 浅色 / 深色

通话页
├─ 返回或结束
├─ 连接、聆听、回应、静音等状态
└─ 字幕展开 / 收起

历史会话
├─ 按日期分组的列表
└─ 只读详情
```

返回操作不应意外结束正在进行的会话；通话中的返回、系统返回键和结束按钮需要分别验证。通话页不提供模式切换，模式在下一次会话开始前选择。

## 页面规格

| 页面 | 进入方式 | 必要内容 | 交互边界 |
| --- | --- | --- | --- |
| 首页 | 启动 App 或结束会话后 | 当前模式、模式切换、主开始按钮、历史入口、设置入口、当前配置是否就绪 | 未配置时主路径引导连接配置；已配置时两次点击内开始；不要在首页显示真实 endpoint 或 API key |
| 通话页 | 首页点击开始 | 模式、会话状态、可感知的听说状态、静音、结束、字幕展开 / 收起 | 用户讲话时可打断当前播报；结束后释放会话资源并回到首页；不在页面上编辑模型参数 |
| 历史列表 | 首页点击历史会话 | 日期分组、模式标识、可读的时间或标题、空状态 | 只显示本机已有记录；无记录时给出清楚的空状态和返回入口；不显示凭据或完整 endpoint |
| 历史详情 | 历史列表选择一条 | 会话日期、模式、只读文字内容及可用的基本信息 | 不自动恢复上下文；只读查看；录音是否存在取决于后续确认，不在静态稿中暗示必然保存录音 |
| 设置首页 | 首页点击设置 | 模型参数、连接配置、外观三个清晰分组 | 模型参数与扫码导入是不同入口；当前会话中修改参数不重启当前会话 |
| 模型参数 | 设置首页点击模型参数 | GPT-Live-1 实时语音参数、后端模型开关与参数、保存操作、变更提示 | 参数范围以实际服务验证为准；保存后下一次会话生效；保存失败保留未保存状态并说明原因 |
| 连接配置 | 设置首页点击连接配置 | 已导入状态、可读模型或部署名、扫码导入 / 更新、测试并保存 | API key 不显示；真实 endpoint 不在列表显示；导入、解密、测试失败不覆盖原有可用配置 |
| 外观 | 设置首页点击外观 | 跟随系统、浅色、深色 | 主题切换即时预览并持久化；不能只反转颜色，文字、状态和按钮仍须有足够层级 |

## 模型参数页的内容边界

页面可以用用户易懂的标签呈现以下参考字段，但要在实现前依据实际服务删减或调整：

- 应用侧会话偏好：音色、语言、助手指令、单次会话时长；对应现有 demo 的 `voice`、`language`、`instructions`、`sessionMinutes` 参考。
- 实时语音会话请求中已见的字段：`model`、`instructions`、`audio.output.voice`；连接所需的 `delegation` 与 WebRTC transport 属于内部链路，不应伪装成普通可调模型参数。
- 后端接入设置中已见的字段：是否启用、模型或部署名、推理强度、最大输出长度、联网搜索；对应现有 demo 的 `enabled`、`model`、`reasoningEffort`、`maxOutputTokens`、`webSearch` 参考。实际请求映射为 `model`、`max_output_tokens`、`reasoning.effort` 和 `web_search` 工具；启用开关是应用行为，不是请求中的模型参数。

这里要区分应用偏好和模型原生参数：现有 demo 中 `sessionMinutes` 是应用侧的会话结束策略，不是模型 API 参数；`language` 与 `instructions` 会参与生成会话指令，也不能直接等同于服务端原生采样参数。后端字段是否可用取决于实际后端服务。规格不新增 `temperature`、VAD 或其他未验证参数，也不把 demo 的参数范围当成所有模型的能力。

上述参考可由现有实现核对：[demo/server.mjs](../../demo/server.mjs)（第 119、227 行）和 [demo/backend.mjs](../../demo/backend.mjs)（第 30 行）。这些源码只是行为参考，不表示移动端已经支持对应字段。

保存成功后显示“下次会话生效”的明确提示。当前会话继续使用启动时的参数，不因为返回设置页或保存而静默重启。

连接地址只从普通列表和概念图中省略；扫码解密后的核对页仍需向设备使用者显示实际服务地址与模型，再由用户触发测试并保存。不能因为隐藏地址而让扫码后自动向未知目标发送凭据。

## 视觉与状态

### 主题

浅色和深色都使用同一信息层级、控件位置和操作文案。深色模式要单独设计背景、卡片、输入框、主要按钮、次要按钮、错误提示、连接状态、字幕和禁用态，避免灰度不足或橙色按钮在深色背景上刺眼。建议默认“跟随系统”，但主题选项的最终入口名称仍在原型中确认。

### 全局状态

- 首次启动、尚未配置：主按钮不可误导为已连接，优先进入扫码配置。
- 已导入未测试：显示配置待测试，不能宣称已就绪。
- 配置就绪：显示已配置状态和可读模型名，不泄露密钥或完整地址。
- 正在连接 / 已就绪 / 正在听 / 正在回应 / 已静音 / 连接失败 / 重连中：通话页需要能区分这些状态。
- 保存中 / 保存成功 / 保存失败：模型参数页显示保存结果，并保留失败时的编辑内容。
- 历史为空 / 正在加载 / 有记录 / 记录不可读：历史页提供对应反馈，不把空列表当成加载失败。

### 口语练习的交流状态

口语练习页继续以自然交流为中心，不显示考试分数、连续打卡或逐句纠错面板。用户可随时插话、换话题或请求更自然的表达；反馈若进入首版，优先在结束后以简短结果呈现，具体内容仍待确认。

## 验收标准

1. 从首页能清楚找到历史会话和设置；第一次使用时连接配置仍通过二维码流程完成，模型参数页不会要求重新输入 API key。
2. 切换系统主题或在外观页选择浅色、深色后，首页、通话页、历史页、设置页和错误状态都保持可读且层级一致。
3. 有历史记录时，列表按日期并标出通用 / 练口语；打开后能只读查看文字内容和基本信息；没有记录时有明确空状态；任何入口都不会自动恢复上下文。
4. 模型参数页能分别表达 GPT-Live-1 与后端模型的配置范围；保存成功后明确提示“下次会话生效”，当前会话不重启、不切换配置。
5. 连接配置入口与模型参数入口可区分；二维码导入或更新仍能显示已导入状态和可读模型名，API key 与真实 endpoint 不出现在列表或普通展示区域。
6. 通话页的状态设计不削弱核心体验：用户讲话可以打断播报，通用与口语练习均不要求逐句按键；静态声波或动效不作为音频功能已验证的证据。
7. 大字体、较长历史文字、键盘弹出、系统返回、权限拒绝、深色模式和不同屏幕尺寸在可点击原型和 Android 真机阶段分别检查。

## 未决事项

- 历史是否保存录音、保留期限、删除单条 / 全部记录、关闭保存开关是否进入首版。
- 历史详情显示的具体字段、标题生成方式和文字记录格式。
- 模型参数页最终字段、每个字段的合法范围，以及不同语音或后端服务的兼容性。
- 首版练习语言、结束反馈内容、通用模式是否启用独立推理与搜索。

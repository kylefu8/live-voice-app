# 安卓双方录音与独立本机目录

用户确认新会话自动记录用户与助手双方声音，保留到手动删除；录音使用应用私有目录中的 AAC/M4A 和元数据文件，独立于最近 50 条文字历史，避免文字淘汰导致录音消失。空间不足时停止录音并提示，保留可用片段，语音会话继续；不加入云上传、跨设备同步或录音导出。

当前 WebRTC 124 提供公开的麦克风采样回调，但没有 Java 播放采样回调。因此固定 `org.jitsi:webrtc:124.0.0`，通过 Android Gradle Plugin 的字节码插桩精确包装其播放线程中唯一的 `AudioTrack.write(ByteBuffer,int,int)` 调用，复制成功写入的 PCM；保留原调用返回值、异常和缓冲区位置。目标调用数量变化必须让构建失败，升级 WebRTC 时重新检查。相比外放后重新录制，此方式支持耳机；相比录屏采集，不引入每次录屏授权或系统通话音频采集限制。

音频线程仅做有界复制/入队，独立线程对齐、混音并编码；录音故障不传入实时通话线程。输入来自 WebRTC Java 采集帧，可能与软件回声消除后的发送帧略有不同；输出在系统音量和蓝牙编解码前捕获。真实双向内容、耳机、静音和后台行为要以真机验证为准。进程被强行终止可能留下尚未完成的临时文件，不能承诺恢复整段录音。

0.3.1 将每路时间轴改为以采样计数推进：Android 的回调到达时间可能抖动或成批返回，不能把每个缓冲区的回调时间当成其播放位置。首次对齐后连续追加，超过 250 ms 的明显前向中断才重新对齐；按整数采样索引混音，并限制写入时机，避免播放预缓冲超前时把尚未到达的麦克风音频写成静音。测试必须包含抖动、突发回调及不同输入采样率，不能只验证理想时间戳下有音频输出。
